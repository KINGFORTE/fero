## 2024-05-24 - WordPress Theme Performance and Security
**Learning:** Initializing a theme without a standard HTML skeleton and including recursive `get_header()` calls in `header.php` causes critical performance failures (infinite loops) and prevents proper asset management via `wp_head()`. Additionally, storing configuration files like `wp-config.php` (even if renamed to `.db`) in the repository is a major security risk. Broken image links and unused large binary assets also degrade performance and maintainability.
**Action:** Always implement proper HTML5 structure in `header.php`, use `wp_head()` and `wp_footer()` for asset injection, and ensure sensitive configuration files are excluded from version control. Cache `get_template_directory_uri()` in templates with multiple asset references to reduce redundant lookups. Verify all asset references and remove unused binary files to keep the codebase lean.
